# Simulink Modeling Guidelines for LKA

This directory contains the Simulink models and referenced components for the LKA system.

---

## 1. Top-Level Harness Architecture (`lka_main_system.slx`)

The top-level model integrates three modular subsystems using **Simulink Model References**:

```plaintext
                   +------------------------+
                   |  Road / Scenario Env   |
                   |   (Camera Sensor)      |
                   +-----------+------------+
                               | LaneDetectionsBus
                               v
+------------------+   +--------------------+   +-------------------+
|  Vehicle State   |-->|   LKA Controller   |-->|  Vehicle Dynamics |
|     Feedback     |   | (Stanley / MPC)    |   |  (Plant Model)    |
+------------------+   +--------------------+   +---------+---------+
                                                          |
                                                          v
                                                  VehicleStateBus
```

---

## 2. Model Reference Best Practices (MAAB Compliance)

1. **Avoid monolithic models**: Place the plant (`plant_vehicle_dynamics.slx`) and controller (`controller_lka.slx`) in `models/components/` and instantiate them as Model Reference blocks inside `models/top_level/lka_main_system.slx`.
2. **Use strongly-typed buses**: Connect components using `LaneDetectionsBus`, `VehicleStateBus`, and `SteeringCmdBus` generated by `data/bus_definitions/create_lka_buses.m`.
3. **Fixed Step vs Variable Step**:
   - For controller code generation (C/C++ via Embedded Coder): Use a **fixed-step solver** (e.g., `ode4`, step size = `0.02 s` matching `controller.Ts`).
   - For vehicle dynamic exploration: Run the top-level harness with a continuous variable solver (`ode45` or `ode15s`).
