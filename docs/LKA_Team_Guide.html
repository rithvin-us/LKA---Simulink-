1. What the system does

The camera looks at the road. The software finds the two lane lines and decides how much to turn the front wheels so the car stays in the middle of the lane. It outputs a steering angle and the turning radius (R = 1/curvature; + means a left turn). It only steers. In the competition the safety driver controls speed (rulebook K.2.1).

1 Camera1280×720, 20 frames per second
→
2 Lane detectorclassic, team CNN (UFLDv2) or YOLOP; outputs a "lane-line probability" image
→
3 Bird's-eye viewimage turned into a top view in metres
→
4 Line fitleft and right line as curves (offset, heading, curvature)
→
5 LKA controllerKalman filter, safety state machine, pure pursuit / MPC
→
6 Steeringwheel angle (±32°, 60°/s), turning radius
Rule I.2.3: the final algorithm may only use realistic sensors, so no "ground truth" from the simulator. Our competition model therefore uses the camera (LKA_LANE_SOURCE = 1). Ground truth is used only to score runs.

2. Frame rate and timing

The whole control loop runs at a fixed 20 Hz (one step every 50 ms): camera frame, then detector, then controller, then steering command. The vehicle physics in the test bench is calculated at 200 Hz (every 5 ms). One frame (50 ms) of processing delay is built in on purpose, and the Kalman filter compensates for it.

  • Classic detector total ≈ 33 ms per frame, so it keeps up with 20 Hz in real time.
  • Team CNN on the GPU ≈ 40 ms per frame: real time at 20 Hz (it was 68 ms on the CPU). The ONNX add-on is installed and used automatically (LKA.Vision.OnnxBackend = 'auto'); Python onnxruntime on the CPU is the fallback. The simulation stays correct either way: simulation time is not wall-clock time.
  • On the Jetson later: TensorRT. On this laptop more speed needs GPU Coder + CUDA Toolkit + TensorRT (not installed), or the NVIDIA "Prefer maximum performance" power mode.
  • Camera-in-the-loop runs with Unreal take about 90–140 s of wall time for a 60 s scenario.

3. How to run it (step by step)

  1. Open MATLAB R2026a. In the Current Folder panel go to LKA - Matlab (the repository root).
  2. In the Command Window type the line below and press Enter. It sets up the folders, the parameters and the "bus" data types. 
    run('config/startup.m')
  3. Controller test without a camera (fast; figures go to results/mil/): 
    run_lka_mil(Scenarios={'S1_Nominal'}, Controllers=1)
  4. Camera test on the official track. An Unreal window opens; the video goes to results/vision/. 
    run_lka_vision(Detectors={'cnn'})          % team CNN
run_lka_vision(Detectors={'classic'})      % simple detector
  5. Open the live dashboard (browser page with the camera view, steering, speed, GPU load and all results): 
    start_lka_dashboard()
  6. Compare the detectors (table in results/benchmark/): 
    run_detector_benchmark()
  7. Run all tests: runtests('tests'). Unreal tests only run after setenv('LKA_RUN_UNREAL_TESTS','1').
  8. Competition model: integrate_lka_into_skeleton() wires the LKA into aBaja2026.slx. It needs RoadRunner to simulate.
The team CNN file models/perception/team_cnn.onnx (385 MB) is too big for GitHub. Create it once with 
python tools/export_ufld_onnx.py <model_best.pth> models/perception/team_cnn.onnx
or copy it from the team Drive.

3a. Track videos (phone or organisers' video)

Put the videos in vids/ and run

run_lka_on_test_videos()

For every video a folder test_res/<video name>/ is written:

test_res/summary.csv has one row per video. The car in a video does not react to the LKA: the steering and turning radius are what the LKA would command. Speed and yaw come from the road texture (about ±20 %). Give the camera height (CameraHeight) or the real lane width (LaneWidth) and the field of view (HFovDeg, phone ≈ 70°) for correct metres.

3b. Live dashboard

start_lka_dashboard() opens http://127.0.0.1:8050. While a video or an Unreal run is working, it shows the annotated camera frame, progress, LKA state, speed, steering, turning radius, lane position, the time each step takes, and the GPU (load, memory, temperature, power). The Results tab lists every finished video and simulation with buttons to play the videos and open the graphs. It only listens on your own PC.

4. The three lane detectors

NameWhat it isStatus in simulation
classicFinds bright white/yellow thin lines. No AI.Works: 0.086 m max offset
cnnTeam UFLDv2 (ResNet-18, trained on TuSimple, "96 %" = TuSimple point accuracy). Checked against the Colab code: same lane points to 0.06 px. Uses its own ego-left / ego-right lane slots, so kerbs and neighbour lanes are not taken. Fit limited to 18 m ahead.Best: 0.031 m max offset, 100 % in lane
yolop2025 ADAS_2026 model (trained on real dashcam video). The 2025 code fed it BGR colours; it was trained on RGB. Fixed.Works since the fix: 0.122 m, 100 % in lane (sees the rendered left line in only 31 % of frames)

Switch with LKA.Vision.Detector = 'cnn' (or pass Detectors= to the run scripts). How to plug in a new model: models/perception/README.md.

7. Glossary

WordMeaning
Simulink model (.slx)A block diagram that runs as a simulation; blocks pass signals along wires.
BusA bundle of named signals on one wire, for example LaneSensorBus = left line + right line + valid flag.
MILModel-in-the-loop: controller + simulated car, no camera images.
Camera-in-the-loopUnreal renders camera images from the 3D track; the detector reads them.
Pure pursuitSteers towards a point on the lane centre about 6 m ahead.
Kalman filterSmooths the lane measurement and predicts it through missed frames.
ONNXA standard file format for trained neural networks (from PyTorch etc.).
ISO 8855Axis convention: x forward, y left, positive angle = turning left.

8. Common problems

Message / symptomFix

Unreal error "variation in terrain"The car left the road (lane lost). Check the detector.
